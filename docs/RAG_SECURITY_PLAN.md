# Urgent repository exposure and deployment security plan

**Review date:** 18 October 2026. **Scope:** The current `improve/backend-portfolio` checkout, relevant reachable Git history, and the security findings in [`RAG_PORTFOLIO_AUDIT.md`](RAG_PORTFOLIO_AUDIT.md). This document is a plan only. No credential, source file, Git history, remote repository, or deployment was changed or tested here. No secret values are reproduced below.

## Confirmed findings

| Risk | Evidence | Exposure and impact |
| --- | --- | --- |
| Hard-coded admin login | [`app.py`](../app.py#L31-L33) defines a fixed admin email and plaintext password; [`app.py`](../app.py#L83-L98) compares them directly. | Anyone who can read this public repository knows the login. If this code is reachable on a server, they can try the admin upload/delete UI. Treat this password as compromised, especially if reused elsewhere. |
| Hard-coded Flask signing key | [`app.py`](../app.py#L22-L23) contains a fixed session signing key. The admin gate relies on a value in Flask's signed session cookie ([`app.py`](../app.py#L39-L47), [`app.py`](../app.py#L90-L94)). | A public signing key defeats the trust normally provided by the session signature and can allow forged admin sessions. Changing it will invalidate existing sessions, which is desirable here. |
| Debug server on the network | [`app.py`](../app.py#L189-L193) runs with `debug=True` and binds `0.0.0.0` when started via `python app.py`. | On a reachable host, the interactive debugger is a serious code-execution risk. The repository does not prove a server is currently public; check any running or hosted instance. Flask says the development server/debugger must not be used for deployment ([Flask deployment guidance](https://flask.palletsprojects.com/en/stable/deploying/index.html), [Flask debugger guidance](https://flask.palletsprojects.com/en/stable/debugging/)). |
| Historical Gemini API key exposure | `git log main -- .env` shows `.env` in commits `0d679279` and `4aa09215`; each snapshot contains a **different, non-placeholder, key-like** `GEMINI_API_KEY` value. The file was removed from the tracked tip in `74cbec77`. The current tracked `.env.example` is only a placeholder; `.env` and `.env.local` are ignored by [`.gitignore`](../.gitignore#L1-L4). The current local `.env.local` Gemini value does not match either historical value. | Removing `.env` from the latest commit does not revoke keys or remove them from older commits. Both historical keys must be treated as exposed even if no longer used. This review did not test whether either key is still valid. |
| Unsafe chat HTML rendering | [`static/js/script.js`](../static/js/script.js#L49-L50) displays the user's input with `appendMessage`, and [`static/js/script.js`](../static/js/script.js#L71-L76) does the same for Gemini output. Both paths assign the supplied string to `innerHTML` ([`static/js/script.js`](../static/js/script.js#L91-L99)). Gemini is explicitly asked to return HTML ([`src/chatbot.py`](../src/chatbot.py#L225-L249)). | **Yes: this is an XSS sink.** A crafted user message can execute in the sender's own browser; a malicious document or model response could execute in a reader's browser. The prompt's HTML instruction is not sanitization. OWASP recommends `textContent` for plain text and a maintained sanitizer when HTML must be rendered ([OWASP XSS guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet)). |
| Admin actions depend on cookie authentication without CSRF protection | Admin upload and delete use POST forms ([`app.py`](../app.py#L110-L146), [`app.py`](../app.py#L158-L186)); the delete form explicitly adds no CSRF token ([`templates/admin.html`](../templates/admin.html#L141-L151)). | If publicly reachable, a logged-in admin can be induced to submit an unintended request. The template comment claiming a session makes CSRF protection unnecessary is incorrect ([Flask security guidance](https://flask.palletsprojects.com/en/stable/web-security/)). |

**Scan boundary:** I inspected the tracked file list, searched project-authored text files in reachable commits for common Gemini/OpenAI key shapes without printing matches, and examined historical `.env` values only to classify and compare them. No API-key-shaped value was found in the current tracked project source by that pattern scan; this is not a guarantee against every credential format. Historical third-party `.venv` files were excluded from the project-authored finding. Git history was not rewritten.

## Manual actions required from the owner

1. **Check exposure now.** If an instance of this code is running beyond your own machine, restrict or stop it until the code fixes below are applied. In particular, do not run `python app.py` on a public host or reachable LAN interface with its current debug setting. Confirm any old hosting integrations or deployments are actually disconnected; the repository alone cannot verify live exposure.
2. **Revoke both historical Gemini keys.** In [Google AI Studio API Keys](https://aistudio.google.com/apikey) or the linked Google Cloud project's credentials page, identify the two keys previously committed in `.env` and disable/delete them. If an old key still serves another application, create a replacement first, update that application's private environment, verify it, then revoke the old key. Review Gemini API usage/billing for unexpected activity. Google's [Gemini key guidance](https://ai.google.dev/gemini-api/docs/api-key) describes replacement and compromised-key handling. Do not paste keys into GitHub, this document, an issue, or a screenshot.
3. **Rotate any key previously shared outside your private environment.** Earlier messages in this project conversation included a Gemini key and an OpenAI key. If either is still active, replace it and revoke the old one in its provider dashboard. This is separate from the two `.env` history findings; the source scan did not establish that an OpenAI key was committed. [OpenAI's key-management guidance](https://help.openai.com/en/articles/4936850-where-do-i-find-my-op) explains deleting a key.
4. **Prepare new local-only admin secrets.** Choose a unique admin password that is not reused on any other service. Generate a new random Flask signing key when the code is updated. Keep the password (or preferably its hash) and signing key in ignored `.env.local` locally and in a host's secret manager if later deployed. Never commit the values. After the signing key changes, log in again because old sessions will be invalid.

If the historical Gemini keys are already disabled, verify that state in the provider dashboard; no additional rotation of those disabled keys is needed. Revocation matters more than deleting old Git objects, and this plan intentionally does **not** propose a history rewrite.

## Minimal code-fix sequence for approval

These changes should be made together before any public demo or deployment, while keeping the existing Flask pages and `/chat` behavior usable locally.

1. **Remove public admin secrets and disable dangerous defaults.** Read `FLASK_SECRET_KEY`, `ADMIN_EMAIL`, and a password hash from ignored `.env.local` or the process environment. Fail closed when required values are missing; do not retain the published password or signing key as fallback values. Verify the login with a password-hash check. Default the development bind address to `127.0.0.1` and debug to off; allow debug only via an explicit local-development switch. Any future public deployment must use a production WSGI server and private environment configuration.
2. **Close browser and admin request sinks.** Render user messages with `textContent`. Preserve the current formatted bot answers by sanitizing Gemini HTML with a maintained library and a narrow allowlist of presentation tags before `innerHTML`; do not use a regex as an HTML sanitizer. Add CSRF tokens to admin login, upload and delete POSTs, including the dynamically created delete form. Set appropriate session-cookie flags for HTTPS deployment while keeping HTTP localhost usable in development.
3. **Verify the local workflow and security behavior.** Confirm a private local `.env.local` starts the app, normal admin login/upload/delete works, `/chat` still renders safe formatted answers, bad credentials and missing configuration fail, untrusted markup in both user and bot messages stays inert, POSTs without valid CSRF tokens are rejected, and the normal run does not expose the debugger or bind publicly. No live Gemini call is required to test HTML handling; stub its response.

**Approval boundary:** Only this plan file has been added. No source edits, secret rotation, commit, push, deployment, or Git-history rewrite were performed. The owner must perform provider-side revocation/rotation; the code fixes can follow after review and approval.
